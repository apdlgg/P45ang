ASLR / PIE

개념

메모리에 올라가는 영역의 시작 주소를 실행할 때마다 랜덤하게 바꾸는 보호기법. 주소를 예측하기 어렵게 만든다.

  • ASLR: 운영체제가 적용. 스택, 힙, 라이브러리(libc) 등의 주소를 랜덤화.
  • PIE: 바이너리를 위치 독립적으로 컴파일. ASLR과 함께 켜져 있으면 코드(바이너리 자체) 영역 주소까지 랜덤화.

ASLR만 켜져 있고 PIE가 없으면, 라이브러리 주소는 랜덤이지만 바이너리 코드 주소는 고정이다.

동작

ASLR이 켜진 상태에서 같은 프로그램을 두 번 돌리면 주소가 달라진다.

# 1회차
libc base: 0x7f3a1c200000
# 2회차
libc base: 0x7f5e88a00000

그래서 "이 함수는 이 주소에 있다"고 미리 박아 둘 수 없다.

확인

checksec으로 볼 수 있다.

PIE:  PIE enabled      <- 바이너리 주소도 랜덤
PIE:  No PIE            <- 바이너리 주소 고정

우회되는 조건

ASLR은 주소를 "랜덤"하게 하지만 한 실행 안에서는 고정이고, 영역 내부의 상대적 배치는 그대로다.

  • 주소 유출: 실행 중 어떤 주소 하나를 유출하면, 거기서 오프셋을 더해 다른 주소를 계산할 수 있다. (libc 함수 하나 주소 → libc base → system 주소)
  • 고정 영역 이용: PIE가 없으면 바이너리 코드·GOT는 고정이라 그대로 쓸 수 있다.
  • 하위 12비트(페이지 오프셋)는 랜덤화되지 않는다.

정리

항목 내용
ASLR OS가 스택·힙·libc 주소 랜덤화
PIE 바이너리 코드 주소까지 랜덤화
한계 주소 하나가 유출되면 오프셋 계산으로 뚫림
