NX (No-eXecute)

개념

메모리 영역에 쓰기 권한과 실행 권한을 동시에 주지 않는 보호기법. 데이터가 있는 영역(스택, 힙 등)은 실행 불가로 표시한다. DEP(Data Execution Prevention)라고도 부른다.

동작

메모리 페이지에는 읽기(R)·쓰기(W)·실행(X) 권한이 있다. NX가 적용되면 스택·힙 같은 데이터 영역은 RW지만 X는 없다.

그래서 스택에 올려 둔 바이트를 CPU가 명령어로 실행하려 하면, 실행 권한이 없는 페이지라 막히고 프로그램이 죽는다.

확인

checksec으로 볼 수 있다.

NX:  NX enabled     <- 데이터 영역 실행 불가
NX:  NX disabled    <- 스택 등에서 실행 가능

리눅스 매핑에서도 보인다. 스택 라인에 x가 없다.

우회되는 조건

NX는 "새 코드를 올려서 실행하는 것"을 막지만, 이미 있는 코드를 실행하는 것은 막지 못한다.

  • 라이브러리나 바이너리에 이미 존재하는 코드 조각을 이어 붙여 실행한다. (RTL, ROP)
  • 예: system() 같은 기존 함수로 흐름을 넘기면, 새 코드를 올리지 않아도 된다.
