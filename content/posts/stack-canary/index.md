## 개념

함수의 버퍼와 return address 사이에 **랜덤한 값**(카나리)을 하나 넣어 두고,
함수가 끝나기 직전에 그 값이 바뀌었는지 검사하는 보호기법.
값이 변했으면 오버플로우가 일어난 것으로 보고 프로그램을 종료한다.

이름은 광산에서 유독가스를 먼저 감지하려고 데려가던 카나리(새)에서 왔다.

## 동작

카나리 켠 바이너리의 `main`을 디스어셈블하면 세 동작이 보인다.

**함수 시작 — 값 심기**

```asm
mov    rax, QWORD PTR fs:0x28   ; TLS에 있는 카나리 원본
mov    QWORD PTR [rbp-0x8], rax ; 스택에 복사
```

**함수 끝 — 값 검사**

```asm
mov    rdx, QWORD PTR [rbp-0x8] ; 스택에 둔 값
sub    rdx, QWORD PTR fs:0x28   ; 원본과 비교
je     ok                       ; 같으면 정상 복귀
call   __stack_chk_fail         ; 다르면 종료
```

같으면 `je`로 정상 복귀, 다르면 `__stack_chk_fail`로 가서
`*** stack smashing detected ***` 메시지와 함께 죽는다.

## 값의 특징

- **메모리상 첫 바이트(최하위 바이트)가 `0x00`**. 버퍼를 문자열로 출력할 때 널 바이트에서 멈춰서, 카나리 값이 같이 출력되는 걸 막는다.
- 프로그램을 실행할 때마다 값이 새로 정해진다. (같은 프로세스의 스레드끼리는 같은 값을 쓴다.) 그래서 추측이 아니라 유출로 알아내야 한다.

## 우회되는 조건

카나리는 "값이 바뀌었는가"만 본다. 따라서 원래 값을 그대로 다시 써 넣으면 검사를 통과한다.

- **유출**: 스택 내용을 출력해 주는 지점이 있으면 값을 읽어낼 수 있다.
- **정밀 쓰기**: 카나리를 건드리지 않고 그 너머만 쓸 수 있으면 검사에 안 걸린다.
- **fork 서버**: 자식이 부모와 같은 카나리를 쓰면 한 바이트씩 맞춰 볼 수 있다.

## 정리

| 항목 | 내용 |
|---|---|
| 위치 | 버퍼와 return address 사이 |
| 검사 | 함수 종료 직전, 원본과 비교 |
| 관련 | `-fstack-protector`, `fs:0x28`, `__stack_chk_fail` |
