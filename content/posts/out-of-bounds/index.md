## 개념

배열의 유효 범위를 벗어난 인덱스로 접근하는 것.
읽으면 OOB read, 쓰면 OOB write다.

C는 배열 인덱스의 범위를 검사하지 않기 때문에, 음수 인덱스나 크기를 넘는 인덱스를 넣어도
그대로 메모리에 접근한다.

## 예제

```c
int arr[10];

arr[15] = 0x41;   // OOB write: 배열 밖 메모리에 값을 씀
int x = arr[-3];  // OOB read:  배열 앞쪽 메모리를 읽음
```

`arr[15]`는 배열 범위(0~9)를 벗어나지만 컴파일도 되고 실행도 된다.
`arr` 기준으로 떨어진 위치의 메모리를 건드리게 된다.

## 영향

- **OOB read**: 범위 밖에 있는 값(다른 변수, 카나리, 주소 등)을 읽어 유출할 수 있다.
- **OOB write**: 범위 밖에 있는 값(다른 변수, 함수 포인터 등)을 덮어쓸 수 있다.
- 인덱스를 공격자가 정할 수 있으면, 접근 위치도 공격자가 정하게 된다.

## 스택 버퍼 오버플로우와의 차이

- 버퍼 오버플로우: 보통 버퍼를 **연속적으로** 넘겨 써서 뒤쪽을 순서대로 덮는다.
- OOB: 인덱스로 **원하는 위치만 콕 집어** 읽거나 쓸 수 있다. 중간을 건너뛸 수 있다.

## 정리

| 항목 | 내용 |
|---|---|
| 원인 | 인덱스 범위 검사 없음 (음수·초과 인덱스 허용) |
| 종류 | OOB read(유출), OOB write(변조) |
| 핵심 | 인덱스를 통제하면 접근 위치를 통제할 수 있음 |
